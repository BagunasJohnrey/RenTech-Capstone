## Objective
- Build out RenTech (Mylene's Boutique rental app): complete the customer rental flow (payment simulation), staff/customer notifications, themed notification dropdown, AI stylist with guard rails + real product images, personalize the customer Home (signup collects phone/address + item-type preferences, editable in Profile Settings), implement **per-item sales** (admin marks items on sale with optional % off or fixed sale price + optional end date; customers see sale badge/price in Catalog, Collections, and Home; booking charges the sale price), and **email verification on signup** (AUTH_EMAIL_CONFIRM=false default; confirmation link via Supabase; verify-email landing; unconfirmed logins blocked with a friendly hint).

## Auth Hardening (Phases 1-6 complete + Performance Wave W1)
- **Phase 1 — httpOnly cookie sessions**: `middleware/cookies.ts` sets `rt_access` (JWT expiry) + `rt_refresh` (60d) as HttpOnly/SameSite=Lax cookies (Secure in prod), `Path=/api`. `middleware/auth.ts` reads cookie first, falls back to `Authorization: Bearer`. `POST /api/auth/refresh` refreshes the session. `middleware/csrfGuard.ts` uses Origin allowlist on mutating routes. Frontend `authSession.js` stores only `rentech_authed` flag; `api.js` 401-retry calls `/auth/refresh`; `useAuth.jsx` boots via `/auth/me`.
- **W1.1 — Server-side backup codes**: `mfa.service.ts` generates 10 one-time backup codes via `crypto.randomBytes(8).toString('hex')` (64-bit entropy each). Codes are generated server-side, never persisted by the client, and consumed one-time (`consumeBackupCode` removes from the stored JSON array).
- **W1.2 — Local JWT verification**: `middleware/jwtVerify.ts` verifies Supabase access tokens offline (HS256 via `SUPABASE_JWT_SECRET` + RS256 via cached JWKS). `auth.ts` middleware uses local verify first, falls back to `supabaseAdmin.auth.getUser()` on failure. Eliminates the per-request Supabase round-trip (~50-150ms saved per request).
- **W1.3 — Profile cache**: `utils/profileCache.ts` caches the auth-relevant profile slice (userId → role, email, name, phone, mfaEnabled) for 30s in-process. `auth.ts` reads from cache, falls back to Prisma. Cache is invalidated on `updateMe`, MFA enable/disable, and staff removal. Single backend instance shape; multi-instance ready (swap store behind same interface).
- **W1.4 — AAL from JWT**: `jwtVerify.ts` extracts `aal` claim from the JWT payload. `requireMfaAdmin` (`middleware/rbac.ts`) reads `req.aal` set by `auth.ts` — no extra DB round-trip for the admin MFA AAL check.
- **Phase 2 — Email verification + password reset**: `AUTH_EMAIL_CONFIRM` (default `false` = verification REQUIRED; set `true` for a frictionless demo) gates customer signup: when false, `signupCustomer` uses the **anon-key public `signUp`** (`supabaseSignUp` in `config/supabase.ts`) with `emailRedirectTo: /verify-email` — only the public endpoint triggers Supabase's confirmation email (service-role `admin.createUser` never does). Unconfirmed users get NO session (response `requiresVerification: true`; controller skips cookies; `Login.jsx` step 3 shows "Check your inbox" instead of auto-login) and `loginUser` returns "Please verify your email address first" for `email_not_confirmed` errors (safe — GoTrue only emits that after a correct password). `POST /auth/verify-email` consumes the signup `token_hash` via `verifyOtp({ type: 'signup' })` and mints session cookies; `VerifyEmailView.jsx` (public `/verify-email` route in App.jsx, reads token from search+hash) completes the flow. Staff accounts (admin-created) are always auto-confirmed (`email_confirm: true`). `POST /auth/forgot-password` always returns 200 (no enumeration), pure Supabase delivery via `resetPasswordForEmail` (no actionLink, no third-party mailer); `POST /auth/reset-password` (recovery-hash → updateUserById → revokeAllUserSessions → cookies). `ForgotPasswordView` (reset-only; forgot step inline in `Login.jsx`) + `VerifyEmailView` exist.
- **W2.6 — Proactive token refresh**: `middleware/cookies.ts` sets a non-httpOnly `rt_expires_at` cookie (epoch ms) alongside session cookies. `frontend/src/utils/authSession.js` `scheduleProactiveRefresh()` reads it and schedules a `setTimeout` to call `/auth/refresh` ~5 min before expiry, preventing mid-session 401s.
- **Phase 3 — OAuth server-side redirect**: `GET /api/auth/oauth/redirect` calls Supabase `signInWithOAuth` server-side → 302. `GET /api/auth/oauth/callback` exchanges code (PKCE) → profile; incomplete → `rt_oauth_pending` cookie → 302 to `/oauth-details` → `POST /oauth/details` finishes. `Login.jsx` Google button uses `window.location`.
- **Phase 4 — Password policy**: min 12 chars + upper/lower/digit/symbol in `signupSchema` + `createStaffSchema`; synced in `Login.jsx` validator/helper text.
- **W2.7 — MFA pending-session cookie**: login sets `rt_mfa_pending` httpOnly cookie (15-min TTL, holds the challenge tokens). `mfaChallenge` controller reads tokens from this cookie — the frontend only sends `{ code }`. Backward-compatible fallback to body tokens for older clients.
- **W2.8 — Session revocation on security events**: `auth.service.ts` `revokeAllUserSessions(userId, accessToken?)` calls `supabaseAdmin.auth.admin.signOut(jwt, 'global')` to invalidate all sessions. Called after password reset (before minting new cookies) and on MFA disable (reads access token from cookie, then clears session cookies).
- **Phase 5 — Admin-only MFA (TOTP)**: `Profile` has `mfaEnabled Boolean @default(false)`, `totpSecret String?`, `backupCodes Json?`. Backend: `mfa.service.ts` generates/verifies TOTP (RFC 4226, 6 digits, 30s window ±1); `auth.controller.ts` `/mfa/setup` returns QR URI; `/mfa/enable` verifies code + stores backup codes; `/mfa/disable` clears + revokes all sessions; `/login/mfa` accepts TOTP or backup code. `requireMfaAdmin` middleware (in `middleware/rbac.ts`) enforces MFA on admin routes: Admin + no MFA → 403 `mfa_enroll_required`; Admin + MFA enabled but AAL < 2 → 403 `mfa_challenge_required`. Wired onto `auth.routes.ts` staff management + `inventory.routes.ts` `/analytics` + `settings.routes.ts` `/rules` + `/sms-templates` + `/integrations-status`. Frontend: `ProfileSettingsView.jsx` has enable/disable toggle (QR via `qrcode.toDataURL` server-rendered data-URI + 6-digit input + backup codes); `Login.jsx` has full-screen TOTP challenge when login returns `requiresMfa: true`. Manual step: enable TOTP in Supabase dashboard.
- **Trust-this-device (rt_mfa_trusted)**: optional 30-day httpOnly cookie, HMAC-bound to the account email (`buildMfaTrustedValue`/`setMfaTrustedCookie`/`isMfaTrustedCookie` in `middleware/cookies.ts`). Set when the admin checks "Trust this device for 30 days" on the login TOTP screen (`trustDevice: true` on `/auth/login/mfa`) or right after `mfaEnable`. **Survives logout on purpose** (NOT cleared in `clearSessionCookies`): while valid, `/auth/login` skips the TOTP prompt (`loginUser(email, password, trustedDevice)`), and the controller mints the `rt_mfa_verified` marker for that login so MFA-gated routes stay open. Per-account bound — a cookie minted for one email doesn't skip another admin on the same browser. Expires in 30 days; no "remove trusted devices" UI yet.
- **W3.9 — totpSecret encryption at rest**: `utils/crypto.ts` provides AES-256-GCM `encryptField`/`decryptField` (format: `v1:<nonce>:<ciphertext+tag>`). `mfa.service.ts` encrypts on write (`setTotpSecret`); `auth.controller.ts` decrypts before TOTP verification (`mfaEnable`, `mfaChallenge`). Legacy plaintext secrets (no `v1:` prefix) pass through unchanged. `scripts/migrate-totp-secrets.ts` script encrypts existing plaintext rows. `MFA_SECRET_KEY` env var required in production — **it is ALSO the HMAC key for the `rt_mfa_verified` marker (see marker below) and was once missing from `backend/.env`, which silently disabled MFA-verified sessions (403 `mfa_challenge_required` on every MFA-gated admin route while login itself succeeded) — `setMfaVerifiedCookie` now logs a warning when unset.**
- **Phase 6 — Logout revocation**: `/auth/logout` revokes refresh token via `supabaseAdmin.auth.admin.signOut(refreshToken)` (session-scoped), clears cookies + flag. Access token stays valid ≤1h (stateless JWT residual).
- **`getProfile` sanitization**: `auth.service.ts` strips `totpSecret` + `backupCodes` from the profile before returning to `/auth/me` (security: prevents MFA secret leakage).
